## DESIGN SPECIFICITY VERDICT

**Author-specific**: This interface is authored for self-hosted AI security systems. The SOC analyst workstation metaphor—near-black backgrounds (`#0a0a0b`, `#111113`), threat color coding (green=verified, amber=pose, blue=yolo, red=destructive), monospace data displays, dense grids—would feel alien in any other product context. The verification timeline (YOLO confidence → face match → pose check) is uniquely meaningful to security-conscious users who demand explainable AI.

However, some elements are category-interchangeable: Login tab styling follows generic shadcn/ui patterns; error states could be any SaaS dashboard.

## OVERALL IMPRESSION

The UI successfully adopts a Security Operations Center (SOC) aesthetic—dense, dark, data-rich—that matches the self-hosted security product context. The biggest opportunity is **information architecture**: the dock navigation conceals locations, and users must memorize paths. Secondary opportunity: keyboard navigation depth and power-user affordances for the technical hobbyist user base.

## WHAT'S WORKING

1. **Threat Color System**: The TIER_COLORS mapping in EventsPage (lines 62-68) assigns distinct colors to verification tiers (blue=YOLO, green=face, amber=pose) with matching backgrounds. This encoding at a glance tells users *why* an event was classified, building trust in the AI.

2. **Verification Timeline as Trust Mechanism**: The human verification pipeline visualization (EventsPage's `getVerification()` function) shows the exact classification path—YOLO ≥0.90 confidence, face detection, pose skeleton. This meets "inspectable by default" principle and eliminates "crying wolf."

3. **Dock Navigation with Real-time Status**: MacDock component displays LIVE/OFFLINE connection state with animated pulse for live connections. The `backdrop-blur-xl` with `rounded-t-lg` gives a "floating panel" aesthetic over camera feeds.

## PRIORITY ISSUES

### **[P1] Hidden Navigation / No Breadcrumbs** (audit)
The MacDock puts ALL navigation items in a hidden dock. After 10 clicks between Live, Events, People, Settings, users cannot see their location. Dark theme makes even active link indication faint (`bg-white/[0.08]`). Add breadcrumb trail for deep pages (Settings sub-sections, Event detail view).
**Fix**: Add contextual breadcrumbs: `Home > Events > Event #1234`. Replace dock icons with text labels on hover for primary nav.
**Suggested command**: `/impeccable audit`

### **[P1] Missing Keyboard Shortcuts for Power Users** (optimize)
Tech-savvy self-hosters expect shortcuts: `F` for fullscreen cameras (present in hotkey listener), but no shortcuts for common actions: `S` for Settings, `E` for Events, `↑/↓` for camera navigation, `Delete` to archive event, `Cmd+K` for quick search. Alex (power user) abandons when forced to click-dance.
**Fix**: Register keyboard shortcuts via `useHotkeys` or native keydown handlers. Display shortcuts in tooltips.
**Suggested command**: `/impeccable optimize`

### **[P2] Decorative Grid Background** (polish)
Detector found `.soc-grid` class at `index.css:261-266`. The 40px grid overlay adds visual noise that fights with the data-dense SOC aesthetic. It's particularly visible in Settings and Login pages where the grid fights with card backgrounds. Remove from non-datalayer surfaces.
**Fix**: Remove `.soc-grid` from body. Keep only in camera grid backgrounds if needed.
**Suggested command**: `/impeccable polish`

### **[P2] Inconsistent Form Validation UX** (clarify)
Login form shows inline errors (`validationErrors.username` etc.) but validation messages are generic. Settings form validates but doesn't persist errors visibly on disk—user loses work on refresh. Error states lack color-coded icons. Jordan (first-timer) can't tell if validation failed or just slow submit.
**Fix**: Add error icons, use form-level validation summary, ensure draft/auto-save state.
**Suggested command**: `/impeccable clarify`

### **[P2] Touch Target Size Inconsistency** (layout)
Dock navigation uses 44px+ targets for buttons under active state (see AdaptiveCameraGrid `min-h-[44px]`), but dock items use `px-3 py-1.5` (~36px visual height). Mobile users struggle.
**Fix**: Increase dock item padding to `px-4 py-2` minimum 44px height.
**Suggested command**: `/impeccable layout`

### **[P3] MFA QR Code Styling** (delight)
MFA setup displays QR code with `w-48 h-48` but lacks QR-specific affordances: no "Can't scan?" text link for manual entry, no copy button for secret key, no size adjustment. Riley (stress tester) might paste secret into app directly.
**Fix**: Add "Can't scan?" link below QR that switches to text input mode for secret entry.
**Suggested command**: `/impeccable delight`

## PERSONA RED FLAGS

### Alex (Impatient Power User)
- **No keyboard navigation for settings save/reset** - must click buttons
- **Dock icons have no tooltips on first visit** - expected tooltips show after hover, but initial state is icon-only
- **Event pagination requires clicking page numbers** - could arrow keys
- **Slideshow interval buttons (3s/5s/10s) are small touch targets in fullscreen**

### Sam (Accessibility-Dependent User)
- **Dock navigation icon-only on mobile** - icon labels only appear on `sm:inline`, so screen readers on mobile see unlabeled icons
- **QR code on MFA screen has no `alt` attribute explaining it's a backup code** - only `alt="MFA QR Code"`
- **Dark background `#050505` vs text `#f5f5f5`** - contrast ratio ~1.8:1 (fails WCAG 4.5:1). The CSS tokens use HSL but actual values don't match intended contrast
- **Radial glow overlay (`radial-glow`, `radial-glow-alt`) is decorative but may trigger motion sensitivity**

## MINOR OBSERVATIONS

- **Theme persistence flashes**: `theme-init.js` injects theme before React loads, causing FOUC on first paint
- **Form fields lack `autocomplete` attributes** (username, email, password)
- **Logout dropdown appears from dropdown-menu, but item styling conflicts with destructive color** (`hover:bg-destructive hover:text-destructive` on `LogOut` item)
- **Spinners use `border-primary border-t-transparent` pattern** - good for color awareness, but inconsistent with other spinners that use `animate-spin` utility
- **Timelapse page** (not fully read) potentially missing empty state handling for no timelapse available
- **Event images use `loading="lazy"`** but 4-up grid creates CLS as images load

## QUESTIONS TO CONSIDER

1. **Should the dock become a sidebar on desktop?** The SOC metaphor favors horizontal bottom dock, but sidebar would improve discoverability and reduce click distance.
2. **Could verification status badges become filterable?** Users want to view only "face-verified" events—could add filter chips.
3. **Is the grid background an intentional brand element or accidental?** If intentional (cybersecurity grid aesthetic), document in DESIGN.md; if accidental, remove.
4. **Should we add a "quick view" toggle for the data panel?** Power users want events to load in list view without sidebar.
