Implement complete, persistent logging: a `service_logs` database table fed by backend + OpenCV, rotating files on disk, and journald-preserved stdout — all surviving redeploys.

## Architecture

```
backend logger ──warn/error──> service_logs table + ./logs/backend/*.log (rotating, volume-mounted)
opencv service ──WS log_event──> Node persists to service_logs; stdout → journald
go2rtc stdout ──> host journal (journald driver — survives container recreation)
retention cron ──daily purge──> service_logs older than SERVICE_LOG_RETENTION_DAYS (14 default)
GET /api/system/logs ──> query service_logs with filters (route already exists — upgrade impl)
```

## Changes

### 1. Migration `database/migrations/029_create_service_logs.sql`
`service_logs` table: `id UUID, timestamp TZ, service (backend|opencv|go2rtc|system), level (info|warn|error), module, camera_id, message, metadata JSONB` + indexes on timestamp/service/level.

### 2. `server/src/models/ServiceLog.ts` entity + export in `models/index.ts`

### 3. NEW `server/src/services/serviceLogService.ts`
- `recordLog(...)`: fire-and-forget with in-memory queue, batched flush (50 entries or 2s), 1000-entry cap (drops oldest), never throws — logging can never break the app
- `queryLogs({service, level, cameraId, since, limit})` and `purgeOlderThanDays(days)` for the API/retention

### 4. `server/src/utils/logger.ts`
On warn/error, also enqueue to serviceLogService (lazy import avoids circular deps) with `service='backend'`.

### 5. Python log shipping over the existing WebSocket
- `websocket_publisher.py`: `queue_log(level, module, message, camera_id, metadata)` broadcasts `{"type":"log_event",...}` to all connected clients
- `frame_pipeline.py`: `_log()` helper (prints + queues) instrumenting the events that matter for diagnosis: FFmpegReader restarts (warn, with cameraId), pipeline start/stop (info), YOLO init failure (error)
- `pythonWsClient.ts`: handle `type === 'log_event'` → emit; `initializers/services.ts` subscribes → persists with `service='opencv'`

### 6. `SystemController.getLogs/clearLogs` upgrade
Replace in-container file parsing with `serviceLogService.queryLogs` (filters: service, level, cameraId, since, limit ≤ 500). Routes/permissions unchanged (`requireUser` / `requireAdmin`).

### 7. Retention
Daily cron (hooked next to existing cleanup scheduling): purge rows older than `SERVICE_LOG_RETENTION_DAYS` (default 14; documented in `.env.example`).

### 8. `docker-compose.yml`
- backend: mount `./logs/backend:/app/logs` (activates the existing rotating file logger on the host)
- all services: `logging: driver: journald` — stdout lands in the persistent host journal, surviving container recreation

## What you get for future diagnosis
- Query any past incident: `GET /api/system/logs?service=opencv&level=warn&since=...` — camera disconnects, reader restarts, backend errors
- Files: `./logs/backend/*.log` with the existing rotation
- Full stdout history: `journalctl CONTAINER_NAME=sentryvision-go2rtc --since ...` even after rebuilds
